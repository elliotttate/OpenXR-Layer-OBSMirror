# OpenXR OBS Mirror v0.3.0 Beta 10

Beta 10 is about the shape of the recording: why the capture arrives almost
square, why black bars appear beside it on a widescreen canvas, and what to do
about either.

## Fixed

- **The OBS source no longer changes resolution mid-session.** A frame carrying
  only quad layers sized the mirror from the runtime's *recommended* per-eye
  resolution, but applications routinely render at their own scale instead. The
  mirror was rebuilt at the wrong size on every such frame, and OBS dropped the
  source and reattached at a different resolution each time — one log showed
  four reconnects in twenty-five seconds. The mirror now keeps the size the
  projection layer actually uses.

## Added

- **Fill the recording canvas**, on the OBS source. Headsets render each eye at
  close to a 1:1 aspect, so a mirror dropped onto a 16:9 canvas sits between
  black bars. This crops the mirror to the canvas's shape, centred, so the
  source fills the frame with no manual crop values, and it re-crops itself if
  the canvas resolution changes. **It is on by default**, and it is a no-op for
  a source that already matches the canvas — including one whose manual crop
  sliders already produced that shape. Untick it to record the full per-eye
  image with bars.
- **Recording shape buttons** on Control Center's overscan page. Expansion
  percentages scale an almost-square render, so the recording's shape follows
  the *ratio* between them, not either one alone: 130% × 115% is still 1.13:1.
  *Headset native*, *16:9* and *Widest possible* set both sliders from a target
  shape, growing only the axis that needs it.
- **A recording frame readout** that reports the pixel size and aspect the
  current settings produce, from the per-eye size the layer learned during the
  last VR session, instead of two abstract multipliers.

## Improved

- **Overscan and camera smoothing save as you change them.** The Apply buttons
  are gone; moving a slider or a toggle stores the value once the control comes
  to rest. Overscan still needs a VR application restart to take effect, and
  Control Center still says so.
- **The layer reports the runtime's recommended per-eye size** and its aspect,
  so a log makes clear whether a square recording came from the headset or from
  a setting.

## Choosing between the two ways to lose the bars

Filling the canvas is free and immediate, but reaching 16:9 from a square eye
costs roughly 22% off the top and the bottom. Setting the horizontal expansion
to 178% instead makes the mirror natively 16:9, so nothing is cropped and the
recording keeps the whole headset view — for 78% more rendered pixels and a VR
application restart. Above 178% horizontal the two stop competing: filling the
canvas has nothing left to trim from the headset view.

Vertical expansion cannot make a recording wider, so when the goal is a
widescreen frame it only spends GPU time on pixels the frame will not show.

## Install or update

Beta 5 and newer offer this update inside the app: open Control Center, choose
**Yes, update**, and it downloads, installs, and reopens itself.

To install by hand:

1. Close OBS Studio and any running OpenXR application.
2. Download and run `OpenXR-OBSMirror-0.3.0-beta.10-Setup.exe`.

The portable ZIP contains the same self-contained app and payload. Extract the
complete archive before launching it.
