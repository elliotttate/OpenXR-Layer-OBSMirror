# OpenXR OBS Mirror v0.3.0 Beta 7

Beta 7 fixes two causes of a capture source that appears in OBS but shows
nothing.

## Fixed

- **An old copy of the source inside the OBS folder is now detected.** When
  `win-openxr.dll` is also present in the OBS installation's own
  `obs-plugins\64bit` folder, usually left behind by installing the plugin by
  hand, OBS loads that copy first and every capture source runs the old build.
  The source then stays blank even though Control Center reports the installed
  plugin as current. The dashboard now reports this directly and can remove the
  old copy.
- **Applications that submit a single view are now mirrored.** Capture required
  a projection layer containing two views, so VR mods that submit one view,
  including alternate-eye renderers, produced no image at all. A single-view
  layer is now mirrored as mono. The eye selection has no effect for those
  applications, because only one view exists.

## Improved

- **The layer log names why a frame was not mirrored.** The previous "no stereo
  projection layer" message covered three different situations. The log now
  distinguishes an application that submitted no composition layers, one that
  submitted layers but no projection layer, and a projection layer with a
  stated number of views.

## Install or update

Beta 5 and newer offer this update inside the app: open Control Center, choose
**Yes, update**, and it downloads, installs, and reopens itself.

To install by hand:

1. Close OBS Studio and any running OpenXR application.
2. Download and run `OpenXR-OBSMirror-0.3.0-beta.7-Setup.exe`.

The portable ZIP contains the same self-contained app and payload. Extract the
complete archive before launching it.

## Still seeing a blank capture

Open Control Center first and check the dashboard for the old-copy warning
above. If there is no warning and the source is still blank, reproduce it, then
use **Diagnostics > Upload & share logs** and include the copied link. The layer
log now states which part of the pipeline stopped.
