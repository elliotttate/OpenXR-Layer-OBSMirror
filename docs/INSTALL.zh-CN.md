# OpenXR + OpenVR OBS Mirror 安装

> 简体中文 | [English](INSTALL.md) | [项目说明](../README.zh-CN.md)

OpenXR OBS Mirror 在 OBS Studio 中直接采集应用程序渲染的 OpenXR 视图或 SteamVR 的原生 OpenVR 合成器镜像，同时保留头显的正常运行时、视图和追踪。

## 推荐方式：Windows 安装程序

1. 关闭 OBS Studio 以及任何正在运行的 OpenXR 应用程序。
2. 运行下载好的 `OpenXR-OBSMirror-...-Setup.exe`。
3. 接受 Windows 管理员提示。它仅用于将 OBS
   源放入 OBS Studio 的共享插件目录。
4. 保持选中 **打开控制中心** 并完成安装。
5. 确认控制中心里的 **层**、**OBS 源** 和 **运行时** 均为绿色。
6. 打开 OBS Studio，添加 **VR 镜像采集（自动：OpenXR / SteamVR）**。
   它会为正在运行的应用程序选择正确的后端。
7. 通过头显软件正常启动 VR 应用程序。

安装程序不会选择模拟器，也不会替换系统 OpenXR
运行时。如果控制中心报告存在继承来的模拟器覆盖，请使用
**使用头显运行时**，然后重启任何已经打开的启动器。

## 便携版软件包

1. 将整个 ZIP 解压到一个固定文件夹。
2. 关闭 OBS Studio。
3. 双击 `Launch OpenXR OBS Mirror.cmd`。
4. 打开 **安装** 并选择 **安装 / 更新**。
   如果需要安装或替换 OBS 插件，请批准 Windows
   管理员提示。仅层的更新仍然限于当前用户，不需要提权。
5. 重启 OBS Studio，并添加 **VR 镜像采集（自动：OpenXR / SteamVR）**。

便携版控制中心是自包含的；不需要单独安装 .NET。它的安装操作在
应用自身内部运行，不需要 PowerShell。命令行脚本
仍可用于安装和开发者自动化。请保持解压后的文件夹完整，因为它包含原生
层、OBS 源、脚本和应用运行时。

## 录制控制

- **过扫描** 要求兼容的应用程序渲染更宽的录制图像，
  而头显接收到的原始中心视图保持不变。更改过扫描尺寸后请重启
  OpenXR 应用程序。
- **相机平滑** 仅对录制相机进行滤波。它的强度和裁切
  边距会实时更新。
- **UI 层** 可以在录制中纳入或忽略单独提交的 OpenXR 四边形层，
  而不改变头显。
- **仪表盘预览** 在控制中心里显示活动的 OpenXR 共享图像
  或原生 SteamVR 合成器镜像，无需打开 OBS。它仅在
  SteamVR 已在运行时才连接到 SteamVR。

这些仅录制生效的控制属于 OpenXR 层，因此只在自动源
使用 OpenXR 时适用。它的 OpenVR 后端接收已经
合成好的 SteamVR 图像；其源属性则提供眼睛选择、
百分比裁切、自动填充录制画布以及一个重连按钮。

## OpenVR / SteamVR 采集

启动 SteamVR，然后让自动 OBS 源可见。当没有可用的 OpenXR 层
表面时，该源会以后台客户端身份初始化 OpenVR，
并请求 SteamVR 的原生 D3D11 合成器镜像。
它不会注册 OpenVR 应用程序层，也不会更改活动的 OpenXR
运行时，并且它自身从不启动 SteamVR。当需要 SteamVR 专属的眼睛和裁切设置时，
显式的高级 OpenVR 源仍然可用。

OBS 和 SteamVR 必须使用同一块 GPU。如果该源是黑屏，请在其属性中选择
**重新连接 SteamVR**，并检查 OBS 日志中是否有
OpenVR 初始化或 GPU 不匹配的消息。随附的 `openvr_api.dll`
必须与 `win-openxr.dll` 放在一起；重新安装 OBS 插件会恢复
匹配的文件。

请从适度的过扫描开始，例如水平 115% 和垂直 108%。GPU
像素开销大致按这两个值的乘积增长。

## 更新与卸载

在现有版本之上运行更新的安装程序。OpenXR 层使用
不可变的、带哈希版本的原生 DLL，因此可以在不替换
头显会话已加载的 DLL 的情况下暂存更新。重启 OpenXR
应用程序以加载新的层。当 OBS 源更新时请重启 OBS Studio。

使用 **已安装的应用 > OpenXR OBS Mirror > 卸载** 移除控制
中心、OBS 源、当前用户的 OpenXR 层注册以及已安装的层
文件。请先关闭 OBS Studio 和任何 OpenXR 应用程序，以便已加载的文件
能够立即删除。

若要在不卸载任何内容的情况下临时禁用采集集成，请关闭
仪表盘上的 **层** 开关或安装页面上的 **为当前用户启用**。
重新打开它会恢复当前用户的 OpenXR
注册；两个开关始终显示相同的实时状态。

## 故障排查

- 如果仪表盘预览或 OBS 源一直是黑屏，请打开 **诊断**，选择
  **预览诊断**，然后使用 **上传并分享日志**。预览日志
  会记录共享表面是否存在、其帧索引是否在推进、
  源尺寸与格式、GPU 适配器标识以及采样像素亮度。
  这可以区分空闲的生产端、持续推进的全黑帧，以及
  消费端显示问题。本地日志位于
  `%LOCALAPPDATA%\OpenXR-OBSMirror\ControlCenter-preview.log`。
- 如果没有可用的表面或帧，请启动或恢复一个 OpenXR 或 OpenVR
  应用程序。
  如果报告显示存在帧和可见像素，但只有 OBS 是黑屏，请重新打开 OBS
  源的属性，并在上传的报告中比较 OBS 与生产端的适配器标识。
- 如果更新期间 OBS 是打开的，请关闭它并再次运行 **安装 / 更新**。
- 如果只有 OpenVR 源不可用，请确认 SteamVR 正在运行，并且
  已安装的 `win-openxr.dll` 旁边存在 `openvr_api.dll`。
- 如果列出的运行时不对，请使用 **使用头显运行时** 并重新启动
  OpenXR 应用程序。
- 在控制中心 **安装** 页面上查看实时层日志，以了解
  运行时名称、图形 API、交换链尺寸和活动选项。
- 当前构建未签名，因此 Windows SmartScreen 可能会显示
  未识别的发布者警告。请用同一个 GitHub 发行版中的
  `SHA256SUMS.txt` 校验下载文件。
